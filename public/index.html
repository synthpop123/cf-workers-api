Services

Each service lives in src/services/<name>/ and owns the paths under its prefix. They share one router, one snapshot store, one image mirror and one KV namespace, and keep their own databases where they keep history.

Architecture

Writes and upstream reads happen off the request path; the request path reads one KV entry.

Write · events

tokens CLI · collectors→ POST /tokens/…→ D1→ KV · snapshot

A service that owns its writes recomposes its snapshot as the last step of the write, so the view is current the moment the writer hears “accepted”.

Poll · the scheduler

cron→ AirTrail · Koito · Letterboxd · Mastodon · Nintendo→ KV · snapshot+ R2 · artwork

A five-minute heartbeat recomposes the snapshots that read an upstream, each on its own cadence — music and memos every 5 minutes and the home page's Now right after them, movies every 3 hours, flights hourly — and a composition whose bytes did not move writes nothing. The Switch sync runs on its own daily trigger, with its own CPU and subrequest budget. Third-party artwork is copied into R2 once, keyed by content.

Read · public

GET /<service>/site · /misc→ KV→ ETag · 304 if unchanged→ lkwplus.com

No auth on reads, open to any origin with one static CORS header set; HEAD works wherever GET does. Browsers get Cache-Control: no-cache and a strong ETag, so every load asks and an unchanged view costs a ~0-byte 304.

Snapshots

Every public view is a JSON document stored in KV under <service>:site, with its schema version, the day it was composed as of, its ETag and when its bytes last changed in the entry’s metadata — a read is one lookup and no parse. A read recomposes inline only when there is no usable copy: none stored, one of another schema version, or one from another calendar day in Asia/Shanghai, since every window the site draws ends today. If that fails, an earlier day’s copy still answers.

Each body carries schemaVersion, which the site validates strictly before rendering. Bump it with the consumer’s decoder and fixture in lkwplus.com; the Worker ships first.

Read API

  1. GET open ↗

    The four snapshots lkwplus.com/misc draws — flights, movies, music, switch — in one response, assembled from the stored texts without re-serializing. A section with nothing to serve is null; its ETag moves when any section’s does.

  2. GET open ↗

    The tokens dashboard: totals and breakdowns for every range, the daily series sliced by provider, client and model, the device inventory and the reported subscription quota.

  3. GET open ↗

    Switch play time: all-time stats, a year of daily minutes and the catalog ranked by lifetime play, artwork on img.lkwplus.com.

  4. GET open ↗

    The flight map — airports, routes, airline and aircraft tallies and totals — and the last flight flown, by day and airports. No flight number, time of day or seat ever ships.

  5. GET open ↗

    Koito listening history: all-time stats, a dense year of daily plays and the latest listens.

  6. GET open ↗

    The latest Letterboxd diary entries, posters mirrored to img.lkwplus.com.

  7. GET open ↗

    The latest public Mastodon statuses, attachments resolved to what renders; photos copied to img.lkwplus.com as WebP at 640 and 1600 wide.

  8. GET open ↗

    What lkwplus.com shows under Now: the latest listen and film, today’s token totals and the last flight, its airports named by city. Read from the stored views, never their upstreams.

  9. GET open ↗

    Liveness, and the list of services.

Examples

# everything /misc draws, one request
curl "https://api.lkwplus.com/misc"

# revalidate: ~0 bytes back while the view is unchanged
curl -H 'If-None-Match: "<etag>"' -i "https://api.lkwplus.com/tokens/site"

Write API

Every write takes a bearer token — TOKENS_API_TOKEN under /tokens, SWITCH_API_TOKEN for the sync. The CLI joins its base URL with /api/…, so machines run with TOKENS_API_URL=https://api.lkwplus.com/tokens and its routes land under /tokens/api/, verbatim.

  1. POST

    A tokens CLI submission — the official server’s contract and merge semantics. Rewrites the tokens snapshot and, once a day, exports the usage tables to R2.

  2. GET

    Token check used by tokens login --token.

  3. DELETE

    Wipe every stored trace of the account: D1, R2, the quota plans and the snapshot.

  4. POST

    A Codex quota report from the collecting host (POST /tokens/quota/claude likewise). Each plan lands in its own key with its own capturedAt.

  5. POST

    Run the Switch sync now — the same runSync the 01:00 UTC trigger runs.

Operations

  • Deploys are Git-driven: every push to main builds and deploys through Workers Builds, gated by the full check — types plus the vitest suite over real D1/KV/R2 bindings. There is no manual deploy path.
  • Secrets live on the Worker, never in the repo: TOKENS_API_TOKEN, SWITCH_API_TOKEN, PCTL_SESSION_TOKEN, AIRTRAIL_API_KEY. No vendor credential for the quota cards lives here at all — the collecting host reports finished percentages.
  • Backups: D1 Time Travel covers 30 days per database; the tokens service also exports its tables to R2 daily and keeps each device’s raw submission.
