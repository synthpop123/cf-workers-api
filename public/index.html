Read API

Public, with open CORS. Every response carries Cache-Control: no-cache and an ETag, so an unchanged view revalidates as an empty 304.

  1. GET /misc

    The five snapshots lkwplus.com/misc draws in one response: flights, movies, music, portfolio and switch. A section with nothing stored is null.

  2. GET /tokens/site

    Token usage for every range, the daily series by provider, client and model, devices and subscription quota.

  3. GET /switch/site

    Switch play time: all-time stats, a year of daily minutes and the catalog ranked by play time.

  4. GET /flights/site

    The flight map: airports, routes, airline and aircraft tallies and totals. No flight number, time or seat.

  5. GET /music/site

    Listening history: all-time stats, a year of daily plays and the latest listens.

  6. GET /movies/site

    The latest Letterboxd diary entries with mirrored posters.

  7. GET /memos/site

    The latest public Mastodon statuses, photos mirrored as WebP.

  8. GET /portfolio/site

    The portfolio as returns only: a time-weighted index and holdings by weight, overall and per account, with daily closes of each holding and of the S&P 500. No amount, quantity or trade.

  9. GET /now/site

    The home page’s Now tiles: the latest listen and film, today’s tokens and the portfolio’s three-month return.

  10. GET /health

    Liveness and the list of services.

Examples

# everything /misc draws
curl "https://api.lkwplus.com/misc"

# revalidate: an empty 304 while the view is unchanged
curl -i -H 'If-None-Match: "<etag>"' "https://api.lkwplus.com/tokens/site"

Write API

Every write takes a bearer token: TOKENS_API_TOKEN under /tokens, SWITCH_API_TOKEN for the sync. The tokens CLI runs with TOKENS_API_URL=https://api.lkwplus.com/tokens.

  1. POST /tokens/api/submit

    A tokens CLI submission, on the official server’s contract. Recomposes the tokens snapshot and exports the usage tables to R2 once a day.

  2. GET /tokens/api/auth/token

    The token check behind tokens login --token.

  3. DELETE /tokens/api/settings/submitted-data

    Deletes all submitted data: D1 rows, R2 objects, quota plans and the snapshot.

  4. POST /tokens/quota/<plan>

    A quota report for codex, claude or opencode. Each plan is its own D1 row with its own capturedAt.

  5. POST /switch/sync

    Runs the daily Switch sync now.

Architecture

Writes and upstream reads happen off the request path. A request reads one KV entry.

Write

tokens CLI, collectors→ POST /tokens/…→ D1→ KV snapshot

The snapshot is recomposed as the last step of each write.

Poll

cron→ upstream APIs→ KV snapshot+ R2 artwork

A five-minute heartbeat runs each poller on its own cadence; the Switch sync has a daily trigger of its own. A snapshot whose bytes did not change is not written again. Artwork is copied to R2 once, keyed by content.

Read

GET /<service>/site→ KV→ 200 or 304→ lkwplus.com

A snapshot is recomposed on read only when none is stored, or the stored one has another schema version or day (Asia/Shanghai). If that fails, the earlier copy still answers.

Schema versions

Every body carries schemaVersion, which lkwplus.com checks before rendering. A shape change bumps it on both sides, and the Worker ships first.

Operations

  • Every push to main deploys through Workers Builds, gated by the type check and the test suite. There is no manual deploy.
  • Secrets are set on the Worker and never committed. Quota collectors report finished percentages, so no vendor credential is stored here.
  • D1 Time Travel keeps 30 days of each database. The tokens service also exports its tables to R2 daily.
